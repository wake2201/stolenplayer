### M1 runtime layout
- Data dir (default `%LOCALAPPDATA%\TS2MP`): `session.state`, `logs\launcher.log`, `logs\<stamp>_<role>_<instance>\{plugin.log,unity.log}`, `backups\<stamp>\{saves\,playerprefs.reg}`, `client-sandbox\`.
- Game folder additions: `winhttp.dll`, `doorstop_config.ini`, `.doorstop_version`, `changelog.txt`, `BepInEx\` (incl. `plugins\TS2MP\TS2MP.Plugin.dll`, `LiteNetLib.dll`).
- Launcher → game arguments: `-logFile <dir>\unity.log -ts2mp-role host|client -ts2mp-session <hex12> -ts2mp-instance <hex8> -ts2mp-port <n> -ts2mp-logdir <dir> -ts2mp-data <dataDir> -ts2mp-bind <ip> -ts2mp-connect <ip>` (bind/connect added in M2). Without `-ts2mp-role` the plugin is inert.
- **N1:** Host Game passes `-ts2mp-bind <BindAddress, default 0.0.0.0> -ts2mp-port <HostPort>`; Join Game passes `-ts2mp-session join -ts2mp-connect <IPv4 or DNS name>`; the join code only as environment variable `TS2MP_JOIN_CODE` of that game process. Launcher-installed files are listed in `BepInEx\plugins\TS2MP\install-record.txt`; installer backups go to `<DataDir>\backups\install-<stamp>\` / `uninstall-<stamp>\`.

## 3. Game systems

### 3.1 Player, movement, input, camera (V)
- `PlayerScript` (MonoBehaviour, ~730 members): **god object** for the player. Fields: `CharacterController CC`, `PlayerMotorBehavior PMB`, `PlayerCameraBehavior PCB`, `Rewired.Player rewiredPlayer`, `Rigidbody myRigid`, `Inventory invScript`, `GameManager GM`, `Police_Manager PoliceManager`, `CarController current_vehicle`, `int moneyAm`, `float currentXPPoints`, `bool isPoliceChase`.
- `PlayerMotorBehavior`: `CalculateMovement()`, `UpdateGravity(float,float,float)`, `RefreshStates()`, `OnControllerColliderHit(...)`; fields `moveSpeed, runSpeed, crouchSpeed, currentSpeed, targetSpeed, velocityY, inputVector`.
- `PlayerCameraBehavior`: `HandleMouseLook()`, `SetYaw(float)`, `CarEnterRot(float)`, `CarExitRot(float)`.
- `LegsController` (`Animator animator`, `Vector2 inputDir`): first-person legs. `InverseKinematicsController.OnAnimatorIK()`.
- Input is read through Rewired in `PlayerScript`, `PlayerMotorBehavior`, `CarController`, `GameManager`.
- Movement/state fields used by M2 (V, reflection): `PlayerMotorBehavior.isGrounded/isMoving/isRunning/isCrouching`, `moveSpeed/runSpeed/crouchSpeed`; `PlayerScript.CC`, `PMB`, `MainCam`, `is_in_vehicle`, `isHiding`. ## 6. M2 multiplayer protocol (protocol 2, mod 0.2.0)
| Msg | Channel / delivery | Content |
|---|---|---|
| `Welcome` (1) | 0 ReliableOrdered | as M1 |
| `PlayerState` (2) | 1 **Sequenced** (unreliable, drops older) | slot u8, seq u32, senderTimeMs u32, sceneHash i32, feet pos 3×f32, yaw u16 (quantized), MoveFlags u8 = 29 B |
| `SceneInfo` (3) | 0 ReliableOrdered | slot, sceneHash, sceneKey (sorted loaded scene names joined `+`), present |
- Rate: 20 Hz while the local player exists (BepInEx config `Sync.SendRateHz`, 10–30), 2 Hz "not present" otherwise. ≈ 29 B payload + UDP/LiteNetLib headers per snapshot.
- Authority: each peer owns its own player. Receiver validates slot (host expects 2, client expects 1), finite/in-range values, newer seq (wrap-aware). Host relays only validated states (`SendToOthers`; no-op with one client).
- Interpolation: `SnapshotBuffer`, render time = now − clock offset (min-filtered) − 100 ms (`Sync.InterpolationDelayMs`); lerp position, shortest-path yaw; snap on jumps > 8 m or gaps > 1 s; hold last state (no extrapolation by default); speed→0 when data is > 250 ms late; avatar hidden after 3 s without data.
- Visibility (`RemoteVisibility`): connected + local player present + remote present + same scene hash + not in vehicle + not hiding + fresh data.
- Addressing: `SessionNode.BindAddress/ConnectAddress` (default 127.0.0.1). Launcher ini `Role`, `BindAddress`, `HostAddress`, `SessionKey` (LAN requires a key; session id = SHA-256("TS2MP:"+key)[0..16]).

## 7. Shared world state (M3 protocol 3 → M3.1 protocol 4, mod 0.3.1)
| Msg | Direction | Content |
|---|---|---|
| `StateSnapshot` (4) | host → client | epoch u32, headRev u32, n u16, entries (on connect and on resync request; running clocks re-anchored first) |
| `StateDelta` (5) | host → client | epoch, one entry (rev = previous head + 1) |
| `StateResyncRequest` (6) | client → host | epoch, client head (sent on gap / wrong epoch) |
| `StateProposal` (7) | client → host | proposal id u32 (increasing per client process), entry |
| `ProposalResult` (8) | host → client | id, `ProposalCode` (Accepted/Unchanged/NotAuthorized/Invalid/Stale), head rev |
- All on channel 0 ReliableOrdered. Entry = scope u8 (Session/Region/Player), scopeArg i32 (region id or slot), key ≤ 64 chars, rev u32, value ≤ 1024 B. Host commits only; identical value → no new revision; proposals deduplicated per client instance (`ProposalGate`).
- Keys: `region` (Player; host commits its own, client proposes its own), `lastVisit` (Region), **`clock`** (Region: `RegionClock` hours/rate/mode/running), **`sleep`** (Region, client proposal only: `SleepRequest` from/advance), **`calendar`** (Session, host-only: day/week from the host's game).
- **Region clock rules (`RegionClockBook`, host):** owner of a region = host if present, else the client there. Owner publishes its game clock (`HostTimeSampler`: first reading, mode change, rate change > 15 %, prediction error > 0.02 h, or every `World.ClockRefreshSeconds` = 10 s). Host readings are trusted; client readings must come from the owner, stay within 0.1 h of the host model and ≤ 0.05 h/s. Region emptied → frozen (rate 0) at its current time; re-entered → resumes from that time. First entry of a never-seen region → traveller's previous region time (frozen at departure), else the session base clock (host's game clock, i.e. its save); the host's own first region uses its game clock directly. Players entering an established region adopt its time (forced snap). Non-owners follow: < 0.01 h ignore, ≤ 0.25 h blend over 1.5 s, else snap.
- **Client sleep transaction (M3.1.1, `SleepTransaction` in `WorldTime.cs`, `SleepHooks` in `GameAccess.cs`):** start = `PassStart` postfix with `passingTime` (repeated `PassStart` ignored); end = `passingTime` true→false edge polled from `WorldSync.Update` only while a sleep runs (completed sleep), or `StopIt` (abort), whichever first, once. Client sync (reports, corrections) paused from `Begin` to `QuitIt` and while a sleep is active; sampler restarts afterwards. Request id held until the host's result (delta is ordered before the result), disconnect (snapshot on reconnect), region change, or 15 s timeout (→ re-adopt). Reports and sleeps share the per-instance increasing proposal id, so a report delayed past a sleep is `Stale`. Mod 0.3.2, protocol 4 unchanged.

## 11. N1 direct connect (protocol 21, mod 0.11.1)
- Handshake (all in `SessionNode`, crypto in `JoinAuth`): Hello(+client nonce) as LiteNetLib connect data → host `OnConnectionRequest`: `AuthLimiter.AllowRequest` → size ≤ 256 B → `Hello.TryRead` + `Validation.Check(checkSession = JoinKey == null)` → client-nonce replay cache → slot check (`_peer`, `_pending`) → `Accept` + `_pending[peer]` with a fresh server nonce → `OnPeerConnected` sends `AuthChallenge` (17 B) → first message from that peer must be `AuthResponse` (33 B) with the client proof → `CompleteHostHandshake` sends Welcome(+host proof) → client `OnWelcome` verifies the host proof → `Connected`. - Separate-PC review: every persistent store is written by its owning role on its own PC (`Player2Sync` p2inv / `VehicleSync` fleet: host only; `p2pending-client.dat` + `client-sandbox`: client only, the pending report is validated against the host record before commit).
